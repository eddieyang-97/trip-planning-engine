**Evidence language:** *coded* means present in source; *CI-tested* means tested in that environment; *deployed* means exact hosted release confirmed; *hosted verified* means a named real endpoint/account/client action was observed; *owner-reported* means reported by a user, not independently reproduced. None alone establishes a full production journey, supplier coverage or verified booking.

## Open boundaries

- **Accommodation [#9](https://github.com/eddieyang-97/trip-planning-engine/issues/9):** the bounded manual/sourced hosted ChatGPT → web → MCP journey and deployment have passed. The **remaining scope limits** are independent Claude acceptance, genuine provider inventory/availability and verified whole-party supplier pricing; no accommodation booking/payment is integrated. Do not confuse a user's web acceptance report plus MCP persisted read-back with an independently observed full browser audit.
- **Flights:** bounded real supplier and connected-client pilots establish particular searches and reads, **not** exhaustive fares, equipment fees, one-way live supplier coverage, a complete same-session journey, reservations or bookability. See [hosted search](hosted-live-search.md) and [client evidence #21](https://github.com/eddieyang-97/trip-planning-engine/issues/21).
- **Passkey security [#35](https://github.com/eddieyang-97/trip-planning-engine/issues/35):** the app reauthenticates credential-management actions in its UI, but Supabase's documented direct passkey APIs have no corresponding per-operation recent-auth policy. A stolen valid bearer token could therefore change credentials directly. Optional friends-only pilot risk acceptance is recommended **but not yet expressly recorded**; password/email recovery stays enabled. Second-account and full OAuth lifecycle evidence remain separate possible follow-ups, not completed guarantees. See [passkey guide](passkeys.md).
- **Production operations:** automatic CI-gated deployment and optional public read-only smoke do not constitute authenticated user-journey acceptance; consult [releases](releases.md).
