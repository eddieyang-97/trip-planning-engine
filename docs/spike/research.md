# Repository and provider findings

Research snapshot: 3 October 2026. Prices below are published USD prices before tax unless stated otherwise. Commercial approval and runtime behavior have not been inferred from documentation. Source inspection covered READMEs, licenses, entry points, domain models, relevant integration/auth files and deployment configuration; this was not an executed usability or security audit.

### Source-level findings and useful ideas

**Ripwords**: [MCP tools](https://github.com/Ripwords/ai-trip/blob/edfd0ad55a86b3d7d1a7c3f9884bf966e6737ec3/server/lib/mcp-tools.ts) share trip writes and access checks with the app, remove share tokens from results and separate read/write tool registration. That is a useful boundary. The inspected wrapper returns JSON in text content; our version should additionally define structured output schemas and tool-effect annotations. [Auth](https://github.com/Ripwords/ai-trip/blob/edfd0ad55a86b3d7d1a7c3f9884bf966e6737ec3/server/lib/auth.ts) contains Better Auth MCP/OAuth support. [Flight lookup](https://github.com/Ripwords/ai-trip/blob/edfd0ad55a86b3d7d1a7c3f9884bf966e6737ec3/server/lib/flight-api.ts) asks AeroDataBox for flight number/date and distinguishes scheduled/revised times; it is not an airfare shopping adapter. [Flight schema](https://github.com/Ripwords/ai-trip/blob/edfd0ad55a86b3d7d1a7c3f9884bf966e6737ec3/server/db/schema/flights.ts) reinforces this distinction. Preserve that time semantics idea. Its itinerary-heavy schema should not be retrofitted into our decision history.

**Jivan**: [stdio entry point](https://github.com/jivanb7/trip-planner/blob/37a6efffe69fc976453d210f3e26c1035ebb0e64/mcp/server/main.py) and [HTTP client](https://github.com/jivanb7/trip-planner/blob/37a6efffe69fc976453d210f3e26c1035ebb0e64/mcp/server/client.py) demonstrate separating MCP from CRUD. The inspected [trip routes](https://github.com/jivanb7/trip-planner/blob/37a6efffe69fc976453d210f3e26c1035ebb0e64/backend/app/routers/trips.py) retrieve trips by ID without an authenticated-user dependency; the [trip model](https://github.com/jivanb7/trip-planner/blob/37a6efffe69fc976453d210f3e26c1035ebb0e64/backend/app/models/trip.py) has no owner relation. This would need fundamental account isolation before hosting. Currency amounts use float; our money contract uses integer minor units.

**MyTripPlanner**: [storage](https://github.com/Prot10/MyTripPlanner/blob/cc66d99ae9891bb6679261b86117056646129468/server/storage.mjs) uses local per-trip JSON; [MCP handler](https://github.com/Prot10/MyTripPlanner/blob/cc66d99ae9891bb6679261b86117056646129468/server/mcp-http.mjs) dispatches via a bridge to the browser. [Hotel search](https://github.com/Prot10/MyTripPlanner/blob/cc66d99ae9891bb6679261b86117056646129468/server/booking.mjs) extracts page cards using Chrome and can fall back to a prefilled URL. A booking link is a useful fallback; extracted cards do not establish a licensed production booking API. Borrow explicit option selection, visible research progress and persistent brief UX. [License](https://github.com/Prot10/MyTripPlanner/blob/cc66d99ae9891bb6679261b86117056646129468/LICENSE) excludes copying under the user's current policy.

**AdventureLog**: [models](https://github.com/seanmorley15/AdventureLog/blob/5673ef5bb5aaa96081bc250ef1d16da8b45977e3/backend/server/adventures/models.py) separate locations from visits and use collection itinerary relations across lodging/transport/items. [Permissions](https://github.com/seanmorley15/AdventureLog/blob/5673ef5bb5aaa96081bc250ef1d16da8b45977e3/backend/server/adventures/permissions.py) distinguish owner/public/shared cases. This is useful future collaboration design evidence, not code to import. [Compose](https://github.com/seanmorley15/AdventureLog/blob/5673ef5bb5aaa96081bc250ef1d16da8b45977e3/docker-compose.yml) demonstrates an operationally concrete self-hosting path; it is much larger than a private flight MCP slice. [License](https://github.com/seanmorley15/AdventureLog/blob/5673ef5bb5aaa96081bc250ef1d16da8b45977e3/LICENSE).

**LetsFG** is the stronger newly found project for the chosen interface, rather than another itinerary clone. [JS SDK](https://github.com/LetsFG/LetsFG/blob/ec95f0eaeddb006f97a55b67961a43974aaa97ea/sdk/js/src/index.ts), [flight models](https://github.com/LetsFG/LetsFG/blob/ec95f0eaeddb006f97a55b67961a43974aaa97ea/models/flights.py) and [README](https://github.com/LetsFG/LetsFG/blob/ec95f0eaeddb006f97a55b67961a43974aaa97ea/README.md) show hosted search, polling and multiple auth paths. README statements vary between no-card and card-connected access and differ from the optional commercial terms in [LICENSE](https://github.com/LetsFG/LetsFG/blob/ec95f0eaeddb006f97a55b67961a43974aaa97ea/LICENSE). Treat free-search, airline-coverage and stable-price statements as vendor claims, not measured facts. Confirm commercial research-only access before adding an adapter; a friend's card-backed consumer token is not our backend credential strategy.

### Build versus reuse

Build the decision/criteria model, evidence lifecycle, party-cost normalization, eligibility/scoring and repeat-search diff. These are the differentiating parts and are missing from the inspected applications. Use maintained protocol/auth/database libraries for infrastructure. Pin versions and inspect their actual licenses/dependencies when scaffolding. Selectively adapt MIT code only when it is smaller and clearer than implementing the needed boundary; retain notices in `THIRD_PARTY_NOTICES.md` with commit/file provenance. No third-party application code has been copied during this spike. Do not fork an entire planner to delete most of it.

**Flight normalization traps:** SerpApi `bags` counts carry-on bags, not snowboards. Outbound results are not enough to identify a fully priced return itinerary: follow departure/booking tokens with a bounded expansion budget. SerpApi's cache lasts one hour; a deliberate refresh uses `no_cache=true`, which cannot be combined with its async mode. Persist the supplier observation/cache time separately from our retrieval time. Search for four travelers in one query; multiplying a one-person price does not prove four seats at that fare. Do not add independently found outbound and return prices and call the sum a quoted round trip. [Parameter documentation](https://serpapi.com/google-flights-api).

**Pilot economics:** cap an initial run at 10 metered requests: one broad search, up to three return expansions, up to three booking-option checks and at most three explicitly budgeted extra attempts. A 1,000-request plan supports roughly 100 such runs if every run reaches the cap, before other endpoints; this is planning arithmetic, not measured consumption. Set an account and global monthly ceiling. Do not retry a timeout with unknown provider acceptance automatically; reconcile a provider search ID where possible.

## Evidence retention and affiliate behavior

Provider capabilities must include a rights profile: permitted uses, fields allowed to persist, retention deadline, attribution and booking-link rules. An unreviewed profile disables production ingestion. Expiry applies to normalized content as well as raw payloads and backups where required. Never assume transforming a restricted payload into our schema removes the restriction.

SerpApi says it retains its search data for 31 days; this describes **its** storage, not a license for our permanent archive. Google Places explicitly restricts caching/storage beyond exceptions. Durable history should preserve our query, decisions and permitted evidence metadata even when a provider fact must be redacted. Show “source content expired” rather than silently inventing the old value. [SerpApi terms](https://serpapi.com/legal), [Places policy](https://developers.google.com/maps/documentation/places/web-service/policies).

Ranking must not be affected by affiliate commission. Preserve approved links and attribution, label commercial relationships when applicable and recheck at the seller before purchase. V1 records an externally completed booking only at the user's instruction; it does not purchase or hold anything.
